# pawmade 美国宠物用品独立站：从本地预览到正式营业

这份项目是 **Next.js 店铺前端 + WordPress / WooCommerce 商品与订单后台**。品牌暂定 pawmade，英文界面、美元计价、面向美国客户。品牌名是设计占位，不代表已注册商标、域名或公司。

## 1. 当前已具备什么

- 响应式品牌首页、狗/猫分类、搜索、价格排序、商品详情与相关商品。
- 浏览器本地购物袋：添加、改数量、删除、刷新保存。
- 品牌介绍、联系页、两篇宠物生活文章、帮助与政策占位页面。
- 从 WooCommerce Store API 读取真实 **USD 简单商品**，约一分钟刷新商品缓存。
- 受保护的结账入口与可安装的 WordPress 桥接插件；支付留在 WooCommerce。
- 标题、描述、站点图和 robots；默认关闭搜索引擎收录。
- 桌面及手机浏览器测试。

**目前默认是演示模式，不接单、不收款。** 六个示例产品是界面设计内容，价格、插图、名称不代表真实商品。政策页面是明确标注的开店前说明，不是审核后的正式销售条款。WordPress 商品接口已连接测试成功，但后台目前只有一个未命名的测试商品。

## 2. 平时怎么运行

在项目目录打开终端：

```powershell
npm install
npm run dev
```

打开 http://localhost:3000 。终端必须保持运行。修改代码保存后，页面会自动更新。

已有 `.env.local` 不要覆盖。参考仓库中的 `.env.example`，把需要的变量合并进去：

```dotenv
COMMERCE_MODE=demo
WORDPRESS_URL=https://fayshop.de5.net
SITE_URL=http://localhost:3000
SUPPORT_EMAIL=
CHECKOUT_ENABLED=false
ALLOW_INDEXING=false
```

`WORDPRESS_URL` 填 WordPress 根地址，不能填 `/wp-admin`。原有的 `NEXT_PUBLIC_WP_API_URL` 仍可作为地址兼容来源。环境变量修改后，停止服务并重新运行。

本机 C 盘曾满，为完成测试，`.next` 构建缓存通过 Windows 目录联接存放到 `D:\codex-build-cache\wp-headless-test-next`。这是本机环境调整，不进入 Git，也不影响 Vercel。D 盘需保持可访问。npm 下载缓存使用 `D:\codex-npm-cache`。正常使用这份源码的另一台电脑不需要这些目录。

## 3. 你在后台管理什么

登录 `https://fayshop.de5.net/wp-admin`：

1. **WooCommerce → 设置 → 常规**：填写真实经营地址、销售区域、美元 USD。不要把商业主体信息交给 AI 编造。
2. **商品 → 分类**：建立 Dogs 和 Cats，别名必须分别为 `dogs`、`cats`。同时建立 Bowls & feeding、Walk & explore、Beds & comfort、Toys & play 等实际使用的分类。一个商品可以属于多个分类。
3. **商品 → 新增**：先创建 3–6 个真实的“简单产品”。填写英文名称、价格、库存、产品说明、短描述和自己的产品照片，然后发布。狗猫通用产品同时勾选 Dogs、Cats。
4. 商品说明写清实际材质、尺寸、重量、适用对象、使用注意事项与清洗方法。运输设置需要正确的重量与尺寸。
5. 删除或改成草稿现有“（无标题）”测试商品，避免它进入正式目录。
6. **WooCommerce → 设置 → 配送**：配置美国可售区域、真实运费和配送方式，明确是否包含 Alaska/Hawaii、邮政信箱等地址。
7. **WooCommerce → 设置 → 税率**：根据真实经营地区与销售税义务配置。是否需要注册、代收或自动税务服务取决于你的经营情况。

第一版明确支持简单产品，不展示可变、组合、外部商品。不支持订阅、组合折扣、商品附加定制字段、独立账号中心、多币种及多语言。需要尺码/颜色变体时，下一步实现真实 variation ID 与属性选择，不能用前端假选项代替。

## 4. 从示例商品切换到真实商品

把 `.env.local` 中的模式改为：

```dotenv
COMMERCE_MODE=live
CHECKOUT_ENABLED=false
ALLOW_INDEXING=false
```

重启开发服务。首页与商品列表读取真实 WooCommerce 数据。后台接口不可用时显示错误状态，不会偷偷切回示例商品。

部署后先打开 `https://你的域名/api/checkout/status`，它只返回状态布尔值，不返回密钥：

```json
{
  "commerceMode": "live",
  "checkoutEnabled": true,
  "bridgeSecretConfigured": true,
  "wordpressConfigured": true,
  "vercelEnvironment": "production"
}
```

如果这里显示 `not-live` 或 `false`，当前部署的配置缺失、被关闭，或值不符合要求；不能只根据控制台里的变量名称判断。检查 `commerceModePresent` / `checkoutFlagPresent` 判断变量是否存在，检查 `vercelEnvironment`、`deploymentUrl`、`commit` 确认当前请求落在哪个部署。保存变量后必须重新部署对应环境，并通过项目的 Production 域名访问。变量值填写 `live`、`true`，不要把引号或 `KEY=` 一起粘贴进值。代码会自动去除首尾空格并统一大小写。

诊断接口始终在请求时读取配置，响应带 `Cache-Control: no-store`。`bridgeSecretConfigured: true` 仅代表密钥达到最小长度，不代表已验证与 WordPress 一致或插件已启用。结账失败时，接口还返回 `COMMERCE_NOT_LIVE`、`CHECKOUT_DISABLED` 或 `BRIDGE_NOT_CONFIGURED` 错误码，便于定位具体原因。

当前适合最多 2,000 个简单商品的初期店铺，商品以服务端分页读取后交给前端筛选。目录很大时，应改成后端分页、搜索和按 slug 查询，减少首屏数据传输。

商品详情会将 WordPress HTML 转为纯文字，以避免直接执行未经清洗的 HTML。需要富文本、表格、更多商品图时，下一步加入受限 HTML 清洗和图库组件。

## 5. 安装结账桥接插件

### 为什么这样结账

购物袋在 Next.js，WooCommerce 的原生购物车在 WordPress 域名。直接把访客跳到 `/checkout`，购物袋不会自动跨域搬过去。本项目用一个小插件完成这个交接。

```text
顾客在 Next.js 加入购物袋
  → 同源 POST /api/checkout 校验 ID 与数量
  → 服务端生成有效期 5 分钟的 HMAC 签名链接
  → WordPress 验证签名、商品、库存、币种
  → 顾客确认替换此结账站点的购物袋
  → WooCommerce 原生结账重新计算价格、税费和运费
  → 支付插件收款，WooCommerce 创建与管理订单
```

签名链接不含姓名、地址、银行卡或价格。价格以 WooCommerce 当时的计算为准。此链接在有效期内可重新使用，但它仅用于确认和重建购物袋，不会自动下单或扣款。GET 请求仅展示确认页；实际修改购物袋需提交确认表单。

### 安装步骤

1. WordPress 后台 → 插件 → 安装插件 → 上传插件，上传 `wordpress/pawmade-checkout.zip`，然后启用。也可以把 `wordpress/pawmade-checkout/` 文件夹放进服务器 `wp-content/plugins/`。
2. 在本机生成一个随机密钥：

   ```powershell
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

3. 将值保存在密码管理器，然后在 WordPress 的 `wp-config.php` 中、`/* That's all, stop editing! */` 之前配置：

   ```php
   define('PAWMADE_CHECKOUT_SECRET', '这里放刚生成的随机密钥');
   ```

4. 在前端 `.env.local` 和 Vercel 服务端环境变量中设置同一值：

   ```dotenv
   WOOCOMMERCE_BRIDGE_SECRET=这里放同一个随机密钥
   ```

5. WordPress 必须使用 HTTPS。主机、CDN、页面缓存插件应排除带 `pawmade_checkout` 参数的请求、购物车和结账页。代码会输出 `no-store` 相关缓存头，但缓存层也需要正确配置，防止把顾客确认链接缓存给其他人。
6. 设置 `SUPPORT_EMAIL` 为可收邮件的真实客服地址，并完成实际政策与付款测试后，才打开 `CHECKOUT_ENABLED=true`。

**密钥不发到聊天里，不提交到 GitHub，不使用 `NEXT_PUBLIC_` 前缀。** `.env.local` 已被 Git 忽略，`.env.example` 只包含占位值。Store API 读取公开商品不需要 WooCommerce 管理员 API 密钥。

插件随源码交付，但还需在你的 WordPress 测试环境中验证与已安装插件、缓存、安全服务、支付网关的兼容性。前端构建与签名验证通过，不能替代真实 WooCommerce 结账验收。

## 6. 配置支付与订单

使用支持你真实注册地区和主体的 WooCommerce 支付插件。可以考虑 Stripe、PayPal 或 WooPayments，具体可用性以你的商户资格与服务商规定为准。

1. 安装、配置支付插件，先打开 sandbox / test mode。
2. 在 WooCommerce 配置订单邮件、发件人域名、SMTP 或邮件服务，确认邮件能送达。
3. 测试真实商品：加购、确认购物袋、美国地址、运费、税费、测试支付、订单状态、库存减少、邮件、退款。
4. 测试失败支付、用户取消支付、库存不足、同一商品多件、过期结账链接，以及不支持配送的地址。
5. 用电脑和手机分别测试，确认返回店铺的体验。现阶段前端购物袋不会根据远端付款成功自动清空；支付、订单详情与退款在 WooCommerce 管理。
6. 通过后再切换正式支付密钥，并做一笔小额实际付款与退款验收。

**不能仅凭首页好看就开始投广告。** 广告前应确保真实商品、配送承诺、客服、政策、付款和售后链路都已经验收。

## 7. GitHub → Vercel

仓库已配置为 `https://github.com/bboy123456/dd.git`。先在本地检查：

```powershell
npm run lint
npm run build
```

需要浏览器回归测试时，先保持本地服务运行，再在另一个终端执行：

```powershell
npm run test:e2e
```

测试默认使用本机 Microsoft Edge。没有 Edge 的 CI 环境可以设置 `PLAYWRIGHT_CHANNEL=chromium`，并用 `npx playwright install --with-deps chromium` 安装浏览器。

建议通过分支审查第一次大改动：

```powershell
git switch -c codex/pawmade-storefront
git add .
git commit -m "Build pawmade pet storefront with WooCommerce checkout bridge"
git push -u origin codex/pawmade-storefront
```

之后在 GitHub 发起 Pull Request，Vercel 可以为分支生成预览。确认后再合并到当前生产分支。如果仓库已连接 Vercel，推送或合并可能触发自动部署。

Vercel 导入这个仓库：

- Framework Preset：Next.js。
- Root Directory：仓库根目录。
- Build Command：`npm run build`。
- 使用与本地兼容的 Node.js 版本；本次开发环境为 Node 24。
- 环境变量在 Vercel 项目 Settings → Environment Variables 配置。
- Preview 环境保持 `CHECKOUT_ENABLED=false`、`ALLOW_INDEXING=false`。正式配置和 Preview 配置分开。
- Production 环境的 `SITE_URL` 填真实 HTTPS 前端域名；建议前端 `www.yourbrand.com`，WordPress `shop-backend.yourbrand.com` 或 `checkout.yourbrand.com`。
- 改环境变量后需要重新部署。
- 商业使用前检查 Vercel 当前套餐的商业使用范围和配额，选择适合经营用途的方案。
